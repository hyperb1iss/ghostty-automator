# Ghostty Automator v1.3.1-auto.2

Ghostty Automator now installs the terminal, CLI, runtime data, and agent skill
together. Agents can diagnose the installation and start a usable terminal
session through two commands. The fork stays on the Ghostty 1.3.1 baseline.

## Install

```bash
curl -fsSL https://raw.githubusercontent.com/hyperb1iss/ghostty-automator/automator/install.sh | bash
ghostty-automator +doctor
ghostty-automator +bootstrap
```

The installer prints an absolute launcher path if `~/.local/bin` is absent from
PATH. Existing installs can use the same command to update.

## Agent workflow

- The diagnostic command (`+doctor`) returns JSON with installation details,
  socket connectivity, capabilities, and the next command.
- The bootstrap command (`+bootstrap`) reuses a running Automator or launches
  one, waits for an initialized surface, and returns its ID. Agents can then
  read the screen, send input, and capture PNG screenshots.
- The bundled terminal automation skill installs into `~/.agents/skills/` with
  a Claude Code skill link. No separate daemon, Python environment, or MCP
  server is required.

## Packaging and runtime fixes

The Linux archives include shared libraries, terminal data, and a launcher that
selects the installed runtime. The macOS archive includes the complete app
bundle and its frameworks. Every archive has a SHA256 sidecar; the installer
checks the checksum before installation. Pinned versions, local archives,
source builds, and installations without skills are supported.

The Linux automation server now delivers keyboard input through GTK and reports
initialized screen dimensions. Shutdown releases the socket and application
ownership before draining pending replies, so a replacement instance can start
while existing clients finish. The client bounds connection and response waits;
bootstrap uses a timer compatible with hosted Linux kernels.

## Validation and platform requirements

Native macOS and Linux builds passed, including the Zig tests, packaging
fixtures, and 15 live Linux TUI checks for input, screen reads, screenshots,
concurrent clients, and lifecycle behavior. A fresh Ubuntu 24.04 installation
also passed the live checks using the hosted release archive.

Linux releases require GTK 4.14+ and libadwaita 1.5+ from the host. Launching a
terminal requires a graphical desktop session. The macOS app build and archive
installation were verified; macOS GUI automation was not exercised. The macOS
archive is unsigned and unnotarized.
